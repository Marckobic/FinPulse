# FinPulse — алерт о кассовом разрыве (n8n)

Раз в день читает журнал движения денег из Google Sheets, считает runway
внутри n8n и, если запаса 45 дней или меньше, отправляет алерт в Telegram
с коротким объяснением от LLM.

Все цифры считает код. LLM только объясняет и ничего не пересчитывает.
Если модель недоступна или вернула пустой ответ, алерт с расчётом всё
равно отправляется.

## Схема

```
Каждый день 9:00  →  Журнал движения денег  →  Расчёт runway  →  Runway <= 45 дн.?
   (Schedule)          (Google Sheets)           (Code)              (IF)
                                                                      ├─ true  → ИИ-комментарии (Groq) → Алерт в Telegram
                                                                      └─ false → ничего не происходит
```

## Что нужно подключить

- **Google Sheets OAuth2** — доступ к таблице с журналом
- **Telegram Bot** — токен от @BotFather и ваш `chat_id`
- **Groq API** — ключ с console.groq.com, модель `openai/gpt-oss-120b`

## Структура листа (вкладка «Log»)

| date | income | expense | comment |
|---|---|---|---|
| 2026-08-01 | 870000 | 0 | Остаток на начало периода |
| 2026-08-03 | 0 | 95000 | Аренда склада |
| 2026-08-07 | 145000 | 0 | Выплата от маркетплейса |

- Первая строка — остаток на начало периода, записывается в колонку `income`.
- Заголовки строго латиницей: `date`, `income`, `expense`, `comment`.
- Даты: `YYYY-MM-DD` или `ДД.ММ.ГГГГ`, код понимает оба формата.

## Настройка после импорта

1. Создать credential для всех трёх сервисов и выбрать их в нодах
   «Журнал движения денег», «Groq Chat Model», «Алерт в Telegram».
2. В ноде «Журнал движения денег» выбрать свою таблицу и вкладку
   (в файле стоят заглушки `YOUR_SHEET_ID`).
3. В ноде «Алерт в Telegram» заменить `YOUR_CHAT_ID` на свой chat_id.
   Узнать его: написать боту, открыть
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, найти `chat.id`.
4. Проверить часовой пояс: `⋯` → Settings → Timezone. В файле стоит
   `Europe/Moscow`. Без явной настройки расписание работает по времени
   сервера, на self-hosted это обычно UTC.
5. Запустить вручную кнопкой **Execute workflow**, затем **Publish**.

## Где менять логику

- **Порог тревоги** — нода «Runway <= 45 дн.?», значение `45`.
- **Формула runway** — нода «Расчёт runway», Code node.

Runway считается по валовому расходу: на сколько дней хватит текущего
остатка при среднем расходе за период, если новых поступлений не будет.
Это консервативная оценка. Средний расход делится на календарные дни
периода, а не на количество строк журнала.

## Проверка перед использованием

- Обе ветки условия: при запасе выше порога сценарий должен молчать.
- Ответ LLM: суммы и даты в комментарии должны совпадать с журналом.
  Модель не должна пересчитывать остаток, runway и средний расход.
